# flb_ml_parser_docker.c Documentation

## Overview

This file contains the implementation for the Docker multiline parser in Fluent Bit. It handles multiline log processing specifically for logs generated by Docker containers.

## Purpose

The primary purpose of this file is to provide a specialized multiline parser for Docker container logs. Docker stores container logs in a specific JSON format, and this parser handles the multiline patterns inherent in this format.

## Key Components

### Docker Parser Creation
- `flb_ml_parser_docker()` - Creates a multiline parser specifically for Docker logs

### Parser Configuration
- Uses JSON parsing for Docker log format
- Handles multiline continuation patterns specific to Docker
- Groups by container stream identifiers

## Implementation Details

### Docker Log Format
Docker stores container logs in a JSON file where each log entry is a JSON object containing:
- `time` - Timestamp of the log entry
- `stream` - Stream identifier (stdout/stderr)
- `log` - Actual log content

### Multiline Handling
Docker logs can contain multiline messages that span multiple JSON entries. According to Docker's log specification:
- A complete log entry has a `log` field that ends with a newline character (`\n`)
- An incomplete log entry has a `log` field that does not end with a newline
- Multiple incomplete entries should be concatenated until a complete entry is received

### Stream Grouping
The parser groups log entries by the `stream` field to ensure that stdout and stderr logs are processed separately and correctly.

## Key Functions

### Parser Factory
- `flb_ml_parser_docker()` - Creates and configures a Docker-specific multiline parser

## Notable Features

### Stream-Aware Processing
The parser correctly handles the separation of stdout and stderr streams, ensuring that multiline messages from different streams are not incorrectly combined.

### Docker Specification Compliance
The parser implements the official Docker log specification for multiline handling, making it compatible with Docker's native log storage.

### Efficient Pattern Matching
Uses optimized pattern matching for identifying multiline continuations in Docker logs.

## Usage Example

### Creating a Docker Parser
```c
struct flb_ml_parser *docker_parser = flb_ml_parser_docker(config);
```

### Typical Docker Log Entry
```json
{"log":"first line\n","stream":"stdout","time":"2021-01-01T00:00:00.000000000Z"}
{"log":"continuation line\n","stream":"stdout","time":"2021-01-01T00:00:00.000001000Z"}
{"log":"final line\n","stream":"stdout","time":"2021-01-01T00:00:00.000002000Z"}
```

The parser would combine these three entries into a single multiline message:
```
first line
continuation line
final line
```

### Incomplete Line Example
```json
{"log":"this is an incomplete line","stream":"stdout","time":"2021-01-01T00:00:00.000000000Z"}
{"log":"this continues the incomplete line\n","stream":"stdout","time":"2021-01-01T00:00:00.000001000Z"}
```

The parser would combine these into:
```
this is an incomplete linethis continues the incomplete line
```
