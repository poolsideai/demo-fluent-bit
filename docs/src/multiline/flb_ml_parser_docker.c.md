# flb_ml_parser_docker.c Documentation

## Overview

This file contains the implementation for the Docker multiline parser in Fluent Bit. It handles multiline log processing specifically for logs generated by Docker containers. This parser is designed to work with the standard Docker JSON log format used by container runtimes.

## Purpose

The primary purpose of this file is to provide a specialized multiline parser for Docker container logs. Docker stores container logs in a specific JSON format, and this parser handles the multiline patterns inherent in this format. The parser recognizes the Docker log specification and properly reconstructs multiline messages that span multiple log entries.

## Key Components

### Docker Parser Creation
- `flb_ml_parser_docker()` - Creates a multiline parser specifically for Docker logs

### Parser Configuration
- Uses JSON parsing for Docker log format with custom configuration
- Handles multiline continuation patterns specific to Docker
- Groups by container stream identifiers (stdout/stderr)
- Uses ends-with pattern matching for the newline character

## Implementation Details

### Docker Log Format

Docker stores container logs in a JSON file where each log entry is a JSON object containing:
- `time` - Timestamp of the log entry
- `stream` - Stream identifier (stdout/stderr)
- `log` - Actual log content

Example format:
```json
{"log":"first line\n","stream":"stdout","time":"2021-02-01T01:40:03.53412Z"}
```

### JSON Parser Configuration
The parser uses the following Fluent Bit parser configuration:
- Backend type: "json"
- Time format: "%Y-%m-%dT%H:%M:%S.%L"
- Time key: "time"
- Skip empty: true
- Time keep: true
- Time strict: false
- Time system timezone: false
- No bare keys: false

### Multiline Handling

Docker logs can contain multiline messages that span multiple JSON entries. According to Docker's log specification:
- A complete log entry has a `log` field that ends with a newline character (`\n`)
- An incomplete log entry has a `log` field that does not end with a newline
- Multiple incomplete entries should be concatenated until a complete entry is received

### Stream Grouping

The parser groups log entries by the `stream` field to ensure that stdout and stderr logs are processed separately and correctly. This prevents mixing of different stream types in the same multiline message.

## Notable Features

### Stream-Aware Processing

The parser correctly handles the separation of stdout and stderr streams, ensuring that multiline messages from different streams are not incorrectly combined. This is achieved through the `key_group` parameter set to "stream".

### Docker Specification Compliance

The parser implements the official Docker log specification for multiline handling, making it compatible with Docker's native log storage. It specifically looks for the newline character (`\n`) at the end of the `log` field to determine when a message is complete.

### Efficient Pattern Matching

Uses optimized ends-with pattern matching for identifying multiline continuations in Docker logs. The pattern specifically looks for the newline character to determine when a multiline message is complete.

### Automatic Flush Mechanism

The parser uses the default flush timeout (`FLB_ML_FLUSH_TIMEOUT`) to ensure that incomplete multiline messages are not held indefinitely, preventing memory issues and ensuring timely delivery of log data.

## Algorithm Overview

The Docker parser processing follows these steps:
1. Incoming log entries are parsed using the JSON parser to extract fields
2. The `log` field is examined to check if it ends with a newline character
3. Entries with newline-ending `log` fields are treated as complete messages
4. Entries without newline-ending `log` fields are treated as continuations and buffered
5. When a complete entry is received, all buffered continuations are concatenated
6. The complete message is flushed to output with preserved metadata

- `key_group` - "stream" (key for grouping by stream)
- `key_pattern` - NULL (no separate pattern key needed)

## Usage Example

### Creating a Docker Parser
```c
struct flb_ml_parser *docker_parser = flb_ml_parser_docker(config);
```

### Typical Docker Log Entry Sequence
```json
{"log":"first line\n","stream":"stdout","time":"2021-02-01T01:40:03.53412Z"}
{"log":"continuation line\n","stream":"stdout","time":"2021-02-01T01:40:03.53413Z"}
{"log":"final line\n","stream":"stdout","time":"2021-02-01T01:40:03.53414Z"}
```

The parser would combine these three entries into a single multiline message:
```
first line
continuation line
final line
```

### Incomplete Line Handling
```json
{"log":"this is an incomplete line","stream":"stdout","time":"2021-02-01T01:40:03.53412Z"}
{"log":"this continues the incomplete line\n","stream":"stdout","time":"2021-02-01T01:40:03.53413Z"}
```

The parser would combine these into:
```
this is an incomplete linethis continues the incomplete line
```
