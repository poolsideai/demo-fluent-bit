# flb_chunk_trace.c Documentation

## Overview

This file implements chunk tracing functionality for data flow monitoring in Fluent Bit. Chunk tracing allows tracking the lifecycle of data chunks as they move through the Fluent Bit pipeline from input to output. This is particularly useful for debugging and monitoring data flow in complex configurations.

The implementation creates a separate pipeline for emitting trace events that track chunk movement through different stages of the processing pipeline.

## Key Functions

### `flb_chunk_trace_context_new()`
Creates a new chunk trace context with the specified configuration. This function initializes the tracing pipeline and sets up the necessary infrastructure for tracking chunk movements.

### `flb_chunk_trace_new()`
Creates a new trace object for a specific chunk. This function is called when a chunk enters the tracing system and assigns it a unique trace ID.

### `flb_chunk_trace_destroy()`
Destroys a trace object and decrements the chunk count in the trace context. Handles cleanup and potential destruction of the trace context when no chunks are using it.

### `flb_chunk_trace_context_set_limit()`
Sets limits on tracing (either time-based or count-based) to prevent excessive resource consumption.

### `flb_chunk_trace_context_hit_limit()`
Checks if the tracing limits have been reached.

### `flb_chunk_trace_do_input()`
Handles input tracing for chunks entering the system.

### `flb_chunk_trace_input()`
Emits trace events for input processing.

### `flb_chunk_trace_pre_output()`
Emits trace events before output processing.

### `flb_chunk_trace_filter()`
Emits trace events for filter processing.

### `flb_chunk_trace_output()`
Emits trace events for output processing.

## Important Variables and Constants

### `struct flb_chunk_trace_context`
Main context structure for chunk tracing that holds:
- Pipeline context for the tracing pipeline
- Trace prefix for generating unique trace IDs
- Trace count for tracking how many traces have been created
- Limit settings for controlling tracing duration
- Mutex for thread safety

### `struct flb_chunk_trace`
Individual trace structure for a chunk that holds:
- Reference to the trace context
- Unique trace ID
- Reference to the input chunk

### `struct flb_chunk_pipeline_context`
Pipeline context for the tracing pipeline that holds:
- Thread information for the pipeline thread
- Input and output instances for the tracing pipeline
- Mutex and condition variables for synchronization

### `FLB_CHUNK_TRACE_TYPE_*` constants
Enumeration values for different types of trace events:
- `FLB_CHUNK_TRACE_TYPE_INPUT`
- `FLB_CHUNK_TRACE_TYPE_PRE_OUTPUT`
- `FLB_CHUNK_TRACE_TYPE_FILTER`
- `FLB_CHUNK_TRACE_TYPE_OUTPUT`

## Notable Implementation Details

### Thread Safety
The implementation uses mutex locks extensively to ensure thread safety when accessing shared trace context data. This is crucial since chunks can be processed concurrently by different threads.

### Separate Pipeline Architecture
Rather than mixing trace data with regular data flow, the implementation creates a completely separate pipeline using an emitter input and a configurable output. This ensures that trace data doesn't interfere with normal data processing.

### Automatic Cleanup
The system automatically cleans up trace contexts when they're no longer needed, using reference counting to track how many chunks are using a particular trace context.

### Limit Management
The implementation supports both time-based and count-based limits to prevent excessive resource consumption during tracing sessions.

### Trace ID Generation
Unique trace IDs are generated by combining a configurable prefix with an incrementing counter, ensuring uniqueness within a tracing session.

### Event Serialization
All trace events are serialized using MessagePack format for efficient transmission and storage.

## Usage Examples

### Enabling Chunk Tracing
Chunk tracing is enabled through the main Fluent Bit configuration:
```ini
[SERVICE]
    chunk_trace_enable true
```

### Setting Trace Limits
Limits can be set programmatically or through configuration:
```c
// Set time limit of 300 seconds
flb_chunk_trace_context_set_limit(input, FLB_CHUNK_TRACE_LIMIT_TIME, 300);

// Set count limit of 1000 traces
flb_chunk_trace_context_set_limit(input, FLB_CHUNK_TRACE_LIMIT_COUNT, 1000);
```

### Creating Trace Contexts
A trace context is typically created when chunk tracing is enabled for an input:
```c
struct flb_chunk_trace_context *ctx =
    flb_chunk_trace_context_new(input, "stdout", "trace-", NULL, NULL);
```

### Emitting Trace Events
Trace events are automatically emitted at various points in the data processing pipeline:
- When chunks enter input processing
- Before chunks are sent to output
- During filter processing
- After output processing completes

These events contain timing information, plugin details, and the actual record data for comprehensive monitoring.
